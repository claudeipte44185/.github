<p>纯净度这件事，事后补救的成本远高于事前查证。实际操作里最省时间的做法是把它排成一条时间线：下单前三天列清单，付款前半小时做四查两问，拿到 IP 的十分钟内复测留档，首周每天五分钟盯三个指标，第三十天做一次续费判断。每一步都有明确的动作和判红线的标准，照着走一遍，比拿到 IP 之后反复猜要靠谱得多。下面按时间顺序展开，节点之间的间隔可以按自己的节奏压缩。</p>

<h2>一、T-3 天：把要查的项先列成一张表</h2>
<p>没有清单的人，查 IP 的顺序通常是"先看价格，出问题再查"。有清单的人先定判据，再去看价格，因为不合格的便宜货等于零。清单只需要四列：查什么、用什么查、合格线、不合格怎么办。</p>
<h3>四类必查项</h3>
<p>黑名单（是否被反垃圾组织收录）、类型归属（是否真属于 ISP 住宅段）、历史滥用（近 90 天被举报次数）、共享迹象（同段被切分成多少份出售）。前三项有公开数据，第四项只能靠间接推断加合同约束。</p>

<h2>二、付款前半小时：四查两问</h2>
<p>这一步的目标不是"确认它好"，而是找证据证明它不好。查得越像找茬，后面越省心。</p>
<h3>四查：黑名单、类型、滥用、同段</h3>
<p>黑名单用 DNSBL 查最快：dig +short 10.113.0.203.zen.spamhaus.org，返回 127.0.0.2 属 SBL、127.0.0.4 属 XBL、127.0.0.10 或 127.0.0.11 属 PBL。这里有个容易误判的点：PBL 收录动态住宅段属于正常设计，单看 PBL 命中不能判定 IP 脏，真正要看的是 SBL 与 XBL。再配合 AbuseIPDB 查近 90 天举报条数与最后举报时间，Scamalytics 看欺诈分，ipapi.is 看 asn.type 是否标为 isp。</p>
<h3>两问：共享率与更换政策</h3>
<p>直接问商家两个数字：这个 IP 目前有多少个客户在用，近 30 天这个 IP 被换过几次。前者多数商家不会给准确值，但可以从回答的含糊程度判断；后者通常会答"免费换一次"，那就问清第二次收费多少、换的时候是否换段。</p>

<h2>三、到手十分钟：复测一遍并把基线存下来</h2>
<img src="/tp.png" alt="纯净住宅IP交付后黑名单复测与基线数据留档">
<p>商家给你的检测截图只代表他查的那一刻，中间可能已经换过手。到手当天必须自己复测，并把结果存成一份文件，后面所有判断都跟这份基线比。</p>
<h3>存哪几项数据</h3>
<p>IP、ASN、country、city、时区、rDNS、DNSBL 返回码、AbuseIPDB 分数、首字节时间。命令层面用 curl -w 记录 time_starttransfer，用 dig -x 取 rDNS，用 date 记时间戳。整份记录存成 CSV，一行一个 IP，方便后面横向比。</p>
<h3>第一次请求别急着登录</h3>
<p>刚拿到的 IP 先访问两三个中性页面，确认出口正常、DNS 没泄漏，再去做登录动作。ipleak.net 能同时看到出口 IP 与 DNS 解析位置，两者国家不一致就先修链路，别在带病环境上做注册。</p>

<h2>四、首周：每天五分钟看三个指标</h2>
<h3>失败率、抖动、验证触发</h3>
<p>失败率按每天 20 次探测算，失败 1 次以内可接受；抖动看 p95 与中位数的差，差值超过 200ms 说明线路拥塞；验证触发记次数，一周内出现两次以上就要怀疑同段有其他用户在高频使用。三项都记在同一个表里，别只凭印象。</p>
<h3>发现问题先分清责任段</h3>
<p>本地网络、代理入口、出口 IP 三段，用 tracert 或 mtr 分段看丢包位置。丢包出现在最后一跳，是出口侧问题，找商家；出现在中间，多为运营商互联拥塞，换时段复测再判断。</p>

<h2>五、第 30 天：续还是换，用数据说话</h2>
<p>把首周与第四周的数据并排放：失败率是否上升、验证触发是否变多、rDNS 是否被改过。三项都在恶化，说明这个 IP 的"新鲜度"在下降，续费前先申请更换；三项稳定，就按原价续，别为了省一点去换一个来路不明的便宜段。</p>

<h2>常见问答</h2>
<h3>被 Spamhaus PBL 收录是不是不能用？</h3>
<p>答：多数情况下不是。PBL 本身就是动态住宅地址的登记表，命中说明这个段被认定为家庭动态段，与"被用于发垃圾邮件"是两件事。要判断污染，看 SBL 和 XBL 是否命中，以及 AbuseIPDB 的报告时间是否集中。</p>
<h3>共享率有没有办法自己测出来？</h3>
<p>答：测不到准确值，只能间接判断。看同段被切分的粒度、晚高峰延迟抖动是否明显、以及同一出口在短时间内的验证触发频率。三项都偏差，就按高共享率对待。</p>
<h3>新 IP 需要"养"多久才能用？</h3>
<p>答：没有统一标准。稳妥做法是首周保持低强度使用，每天固定时段访问，不做批量操作；一周后逐步恢复正常节奏。重点在节奏稳定，而不在时长。</p>
<h3>商家说独享，怎么验证？</h3>
<p>答：无法从外部完全验证，但可以要求写进合同：该 IP 在租期内不分配给第三方、被列入 SBL 或 XBL 时免费更换、提供近 30 天可用率记录。愿意写这三条的可信度明显更高。</p>
